Default Backend

Fallback destination for any request that does not match an explicit task or modelType route.

If you remove the current default backend, the first remaining backend is promoted automatically.

Backend Servers

Backend names are used as routing keys. Renaming a backend updates the default backend, task routing, modelType routing, and local health display references together.

Task Routing

Use task routing for grouped requests such as facial-recognition and ocr. Policy strict always uses the routed backend; fallback can step down to the next routing level when that backend is unhealthy or the request fails. Legacy facial_recognition input is normalized automatically.

CLIP ModelType Routing

Only CLIP is split by modelType. Missing modelType routes fall back to task routing and then the default backend. Policy strict forces the routed backend; fallback retries the next routing level when a routed backend is unhealthy or the request fails.
